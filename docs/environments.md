## Обязательная изоляция

- У staging собственные домен, директория, БД и ограниченный пользователь БД.
- `robots.txt` и `noindex` не заменяют защиту доступа.
- Секреты, резервные копии и журналы не размещаются в `public/`.
- Медиа и runtime хранятся отдельно от заменяемого релиза.
- На staging не копируются реальные клиентские данные без обезличивания.
- Корень нового сайта должен указывать на `public/`; если панель этого не позволяет,
  согласовать с поддержкой эквивалентное разделение публичных и приватных файлов.
  Простой rewrite без доказанной изоляции недостаточен.

## Границы этапов

День 1 — только аудит и документация. День 2 — GitHub, ветки и staging после
утверждения. Дни 3–28 — разработка и проверки в тестовых окружениях.
День 29 — отдельное разрешение владельца на production release.

Целевая доставка: локальная разработка → приватный GitHub → staging → проверки →
production. Ветки main/develop/feature/*/hotfix/* создаются на Дне 2.
Git-откат не восстанавливает БД. Переключение рабочего домена, смена PHP WordPress,
миграции рабочей БД и изменение production document root в День 1 не выполняются.

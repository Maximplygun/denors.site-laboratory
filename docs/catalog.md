## Реализовано

pages/catalog.php — серверный шаблон корневого каталога: хлебные крошки,
заголовки, сетка разделов, контактный CTA и общие header/footer.
catalog.css — стили с отдельным префиксом, 1/2/3 колонки на существующих
breakpoints 40/60rem. Длинные названия переносятся; вся карточка — HTML-ссылка.
Нет внешних изображений, JS, сортировок и фильтров (День 11), товарной страницы
(День 10) или вымышленных остатков и цен.

CategoryLink — только данные представления (title, originalPath), не таблица,
доменная модель БД и не формат импорта. Контроллер/адаптер реальных данных
появятся после их анализа. Путь сохраняется буквально, внешние/protocol-relative
адреса, управляющие символы, query/fragment и ошибочный percent-encoding отклоняются.
Названия и href экранируются. Пустые/неправильно типизированные/повторные
списки не превращаются в успешную пустую страницу.

Application и Router не изменены. `/shop/` и неимпортированные категории
остаются 404. В меню не добавлена ссылка на неготовый каталог.
Нет миграций, подключения БД и предполагаемой структуры категорий.
Новый тест tests/catalog.php запускается также при staging activation до
переключения релиза. Поведение отката и ограничения deploy сохранены.

## Визуальная проверка локально

```bash
php tests/catalog.php
php -S 127.0.0.1:8099 -t public tests/catalog-preview-router.php
```

Открыть http://127.0.0.1:8099/__catalog-preview/.
Это изолированный router PHP development server из tests, не маршрут магазина.
Имена «Тестовый раздел» — явные визуальные fixtures, не данные компании.
Пути берутся из аудиторского CSV только для тестов, не для публикации категорий.
Переходы в эти неимпортированные категории ожидаемо ведут к 404.
Не использовать preview-router для доставки или публичного web-root; после
проверки остановить сервер. Прямой запуск файла на обычном web SAPI отклоняется.

Браузер: 320/375/768/1024/1440 px без горизонтальной прокрутки; 1/2/3 колонки,
осмотр карточек и длинного названия, Tab/видимый фокус, CTA → site-contacts.
Консоль без ошибок/warnings. Дополнительно: PHP lint, 22 catalog checks,
15 application, 748 routing, 13 HTTP-проверок и недоступность /.env.
Проверены MIME CSS, синтаксис Bash изменённого activation, Markdown-ссылки,
SVG/разметка шаблона браузером и git diff --check.
Lighthouse, screen reader, zoom 200%, реальные устройства и Linux self-test
новой версии не выполнены. Формальная полная валидация HTML/CSS не заявляется.

## Что можно проверить на Timeweb

В Git Bash из корня проекта после коммита, ветка feature/catalog, папка чистая:

```bash
denors check
denors
bash tests/http-staging.sh
```

denors отправляет ветку в GitHub и доставляет коммит на staging.
Activation должен вывести `PASS: 22 catalog checks.` вместе с application/routing
проверками и `HTTPS 200 + noindex verified.`. Linux self-test требует PASS.
После доставки `/shop/` и `/__catalog-preview/` должны возвращать 404/noindex;
главная и навигация остаются рабочими. Публичного preview с тестовыми категориями
не создаётся. Вид каталога сейчас проверяется только локальной командой выше.

Для повторного запуска тестов непосредственно из SSH:

```bash
cd /home/c/ci11012/denors.site-laboratory.ru
public=$(readlink -f public_html)
/opt/php83/bin/php "${public%/public}/tests/catalog.php"
```

Production и его БД не затрагиваются. В этой задаче push/deploy не выполнялись.

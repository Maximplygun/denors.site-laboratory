## Реализация и границы

Переиспользуемые PHP-компоненты в resources/views/components/:

- site-header.php — предупреждение о тестовом сайте, название, описание,
  навигация «Главная / Контакты».
- site-footer.php — сведения о компании, телефоны, email, адрес и часы работы.
- site-brand.php — единый текстовый знак названия для шапки и подвала;
  это типографическое представление, не утверждение нового фирменного логотипа.
- site-styles.php — единое подключение общих CSS, включая site-shell.css.

Они подключены к существующей служебной главной и шаблону 404 через фиксированные
пути require на основе __DIR__. Пользовательские данные не выбирают include-файлы.
Общий CSS изолирован префиксами site-*. Токены и палитра Дня 5 не менялись.
Оболочка заполняет высоту экрана, подвал остаётся после содержимого и не перекрывает
его. Шапка не фиксирована и не закрывает фокус или якоря.

Контакты и график сверены 03.11.2026 с публичной страницей
[denors.ru/contacts/](https://denors.ru/contacts/). Добавлены только опубликованные
реквизиты; ИНН, социальные сети, мессенджеры и юридические документы не выдумывались.
Перед production владельцу потребуется подтвердить актуальность реквизитов.
tel: и mailto: открываются только по действию пользователя; автоматических
звонков, отправок и внешних виджетов нет.

«Контакты» ведут к #site-contacts на текущей странице; блок получает фокус.
Ссылки бренда и «Главная» ведут на `/`. Skip-link и ссылка в подвале ведут к #main.
Нет ссылок на неимпортированные страницы, пустых href и фиктивных действий.
Поиск, корзина, полноценное меню каталога и мобильная панель появятся на своих
этапах; на этом этапе простая навигация переносится без скрытия и без JavaScript.
Нет новых URL, редиректов, изменений Router, БД, production или коммерческого
содержимого главной Дня 7. HTTP 404, HEAD/405 и noindex сохранены.

## Проверка владельцем на Timeweb

В Git Bash из корня проекта, в ветке feature/header-footer:

```bash
git status --short
git branch --show-current
denors check
denors
bash tests/http-staging.sh
git rev-parse HEAD
curl -q --fail --show-error https://denors.site-laboratory.ru/denors-release.txt
curl -q --fail --show-error -I 'https://denors.site-laboratory.ru/assets/css/site-shell.css?v=day6'
curl -q --show-error -I https://denors.site-laboratory.ru/day6-missing/
```

До denors рабочая папка должна быть чистой. denors check проверяет Linux
переключение/откат в изолированном каталоге. denors отправляет текущую ветку в
GitHub и публикует коммит только на staging. Нужны PASS, сообщение
`HTTPS 200 + noindex verified.`, совпадение release marker с HEAD, CSS 200/text/css,
неизвестный путь 404/noindex и успешные HTTP-проверки. При отказе не обходить smoke.

В браузере открыть [staging](https://denors.site-laboratory.ru/) и
[неизвестный путь](https://denors.site-laboratory.ru/day6-missing/), обновить кэш.
Проверить header/footer, «Контакты», возврат на главную и клавиатуру; на ширинах
320/375/768/1440 px убедиться, что ссылки/телефоны не обрезаются и нет прокрутки
по горизонтали. Проверять tel/mailto достаточно по адресам ссылок: звонить
и отправлять письмо для приёмки не требуется.

В Network проверить загрузку site-shell.css, остальных CSS и Onest; в Console —
отсутствие неожиданных ошибок. Выполнить Lighthouse Mobile/Desktop (Performance,
Accessibility, Best Practices), проверить масштаб 200% и при необходимости
screen reader. SEO-оценка может учитывать намеренный noindex staging — не удалять
его ради балла. Результаты передать без секретов.

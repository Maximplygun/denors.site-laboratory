## Дополнительные факты аудита

Вывод read-only SSH-проверки владельца:

- CLI PHP 8.3.36: memory_limit 1024M, max_execution_time 0, max_input_time -1,
  upload_max_filesize/post_max_size 5000M, max_file_uploads 1000.
- OPcache extension доступен; opcache.enable=1, opcache.enable_cli=0.
- GD: WebP есть, AVIF нет. Возможности AVIF в Imagick отдельно не измерены.
- Composer, crontab, flock, curl, tar, sha256sum и Git доступны как команды.
  Выполнение Cron-задач и версия Composer отдельно не проверены.
- Shell open_files=1024, processes=40. Это не полное описание ограничений тарифа.
- df показывает общую файловую систему сервера, не квоту аккаунта.
- Лимиты CLI не приравниваются к web PHP. Лимиты загрузки самого приложения
  позднее задаются отдельно, значения 5000M не используются как допустимый размер.

Скриншот тарифа: Century, диск 50 ГБ, занято 29.78 ГБ; сайты 14/35.

это не означает отсутствие лимитов соединений, CPU и процессов.

Скриншот резервных копий: «Создано: 30 копий», выбрана файловая дата 26.10.2026.
Это не доказывает 30 дней хранения и наличие новых каталогов Денорс/БД в копии.
Для завершения аудита открыть список дат и записать самую раннюю доступную,
проверить наличие denors.site-laboratory.ru во вкладке «Файлы» и
ci11012_denorstg во вкладке «Базы данных».
На скриншоте создание ручной копии отмечено как платная услуга 5 руб/день;
эта услуга не заказывалась. Восстановление ничего не запускалось.
Проверку восстановления планировать только в отдельный каталог и отдельную БД:
панель предупреждает о замене текущей копии сайта при восстановлении.

Ориентир для планирования, а не обещанный лимит тарифа: PHP memory_limit 256M,
web max_execution_time 60 с, upload_max_filesize 16M и post_max_size 20M.
Точные значения уточнить по реальным изображениям и экспорту. Импорт должен
обрабатываться пакетами, без требования неограниченного времени web-запроса.

## Проверка через панель

1. В аккаунте определить тип услуги, название тарифа и имя сервера. Для VDS
   сведения о сервере и стеке запросить у администратора; меню виртуального
   хостинга может отсутствовать.
2. Для виртуального хостинга открыть «Сайты» → «Мои сайты» → шестерёнка нужного
   сайта. Записать текущую PHP, каталог, домены и HTTPS. Ничего не переключать.
   Отдельно выяснить доступные версии PHP для будущего staging.
3. В разделе баз данных записать тип/версию сервера и возможность отдельной БД
   с отдельным пользователем. Пароль не включать в отчёт.
4. Проверить наличие SSH, планировщика, настройки защиты директории и резервных
   копий. Названия этих пунктов могут зависеть от панели. Записать лимиты тарифа.
5. Через файловый менеджер только прочитать структуру каталогов. Уточнить у
   поддержки возможность document root `public/`, symlink и действие `.htaccess`.
6. Записать процедуру восстановления и дату последней успешной резервной копии.
   Тест восстановления проводить позднее в изолированном окружении.

Если панель не показывает параметр — получить ответ поддержки, не угадывать.
Не создавать публичный phpinfo на действующем WordPress.

## Проверка через SSH: удалённая Linux shell

Подключение из локального терминала (подставить логин и сервер из панели):

```sh
ssh LOGIN@HOST
```

Далее команды выполняются на Timeweb. Они читают параметры и не меняют сайт:

```sh
pwd
uname -srm
command -v php
php -v
php --ini
php -m
command -v git
git --version
command -v composer
composer --version
command -v mysql
mysql --version
ls -1 /opt
df -h .
df -i .
ulimit -a
```

Отсутствие утилиты — результат проверки, не повод устанавливать её без плана.
`mysql --version` показывает клиент; версию сервера получить отдельно.
CLI PHP не доказывает параметры PHP сайта. Если CLI старый, определить доступную
сборку по `/opt` и документации, повторить команды с её полным путём.

```sh
php -r 'foreach (["memory_limit","max_execution_time","max_input_time","upload_max_filesize","post_max_size","max_file_uploads","opcache.enable","opcache.enable_cli"] as $key) { echo $key,"=",ini_get($key),PHP_EOL; }'
php -r 'echo "PHP=",PHP_VERSION," SAPI=",PHP_SAPI,PHP_EOL; echo "PDO=",implode(",",PDO::getAvailableDrivers()),PHP_EOL; foreach (["mbstring","intl","gd","imagick","fileinfo","openssl","session","curl","Zend OPcache"] as $ext) { echo $ext,"=",extension_loaded($ext)?"yes":"no",PHP_EOL; }'
```

Если PDO отсутствует, второй вызов завершится ошибкой — зафиксировать её.
Для БД использовать интерактивный запрос пароля, а не пароль в командной строке:

```sh
mysql -h DB_HOST -u DB_USER -p -e "SELECT VERSION(), @@character_set_server, @@collation_server; SHOW ENGINES;"
```

Запросы только читают конфигурацию. Не передавать реквизиты в чат.
Web PHP, расширения, OPcache и реальные ограничения сайта подтвердить через
настройки аккаунта/поддержку; позднее допустим временный защищённый диагностический
endpoint на staging с минимальным выводом и обязательным удалением.
Symlink, rewrite, Cron и блокировку приватных путей проверить практически на
отдельном staging в День 2; на Дне 1 получить подтверждение доступности.

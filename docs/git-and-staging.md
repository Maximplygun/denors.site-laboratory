локальный проект уже содержит документацию и собственный .gitignore.

Состояние публикации проверяется отдельно после push.

## Схема автоматизации

Цель: одна локальная команда запускает проверки, отправляет выбранный commit
в GitHub, подключается по SSH и доставляет именно этот commit на staging.

До создания исполняемого deploy необходимо подтвердить:

1. URL приватного репозитория и доступ локального Git к нему.
2. SSH с компьютера владельца и вход ключом с проверкой host key.
3. Фактический web root и возможность переключать отдельные релизы.
4. Защиту staging, путь CLI PHP и процедуру smoke-проверки.

Предпочтительно использовать локальную упаковку отслеживаемых файлов выбранного
commit и передачу по SCP: тогда на хостинге не требуется GitHub-токен с правом записи.
Передача архива не должна заменять .env, uploads, логи и сессии.
На сервере: отдельный новый релиз, проверка PHP, необходимые совместимые миграции,
проверка ресурсов, переключение, smoke-тест и восстановление предыдущего кода при
сбое. Миграции БД не откатываются простой сменой релиза.

Это согласуемая схема, а не готовый механизм деплоя. Скрипт появится после
проверки путей и доступа. Прямой git pull в публичный рабочий каталог не используется.
Production deployment требует отдельного разрешения.

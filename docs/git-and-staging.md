## Схема автоматизации

Цель: одна локальная команда запускает проверки, отправляет выбранный commit
в GitHub, подключается по SSH и доставляет именно этот commit на staging.

Реализованы scripts/deploy/staging.sh и activate-staging.sh. Первый работает
в локальном Git Bash, второй передаётся в Linux shell Timeweb. Доставка — архив
конкретного commit по SCP, с проверкой SHA-256; GitHub-токен на Timeweb не нужен.
Скрипт требует чистую рабочую папку, разрешает только develop и feature/*,
отправляет ветку на GitHub и сверяет удалённый commit.

`denors check` проверяет соединение и запускает изолированный Linux-тест
переключения/восстановления в временной папке. Публичный каталог не меняется.
HTTP в этом тесте заменён Bash-функцией; PHP и flock используются настоящие.
Публичный HTTP проверяется отдельно при публикации.

`denors` дополнительно создаёт releases/ID, проверяет PHP, связывает существующие
storage, .env и shared/uploads и переключает public_html на releases/ID/public.
Первоначальный public_html сохраняется в .deploy/original-public-ID; cgi-bin
продолжает использоваться из сохранённого каталога. Посторонние файлы в первоначальном
корне или непустые assets блокируют первый запуск. Проверочный файл
denors-root-check.txt остаётся только в закрытой резервной папке после переключения.

Smoke-тест требует анонимный 401 для главной, release marker и robots.txt,
затем сверяет commit через HTTPS с авторизацией и проверяет 200 + noindex.
Сертификат проверяется стандартным cURL без -k; переход на HTTP не допускается.
При неудаче возвращается предыдущий публичный корень. Все старые релизы сохраняются.
Ссылка на предыдущий корень: .deploy/previous-public. Автоматическая очистка
старых релизов пока не реализована; следить за местом.
Заглушка — служебная проверка инфраструктуры, а не готовое приложение.
При создании приложения критерии smoke-тестов необходимо изменить.

Скрипт отказывается публиковать миграции БД и composer.json: выполнение миграций
и установка зависимостей должны быть добавлены и проверены при их появлении.
Production deployment требует отдельного разрешения. Защита staging создаётся
командой ниже; текущая опубликованная версия пока открыта и содержит только
служебную страницу без пользовательских данных.

## Пароль staging

Владелец подтвердил наличие /usr/bin/htpasswd на Timeweb.
В локальном Git Bash выполнить один раз:

```bash
bash scripts/deploy/setup-access.sh
```

Скрипт подключается по SSH с терминалом. Логин браузера: denors.
Новый отдельный пароль вводится дважды в htpasswd и третий раз для HTTPS smoke;
перед сохранением повторный пароль проверяется через htpasswd -vi.
Пароли не передаются аргументами процесса и не печатаются.
shared/staging.htpasswd содержит bcrypt-хеш; .deploy/smoke.curl — обратимо
кодированный Basic Auth token для автоматических проверок, с правами 600.
Оба файла находятся за пределами web root и исключены из Git.
Скрипт не заменяет существующие credential-файлы и не включает защиту сам.

После успешного создания файлов выполнить `denors`. При сборке релиза к .htaccess
добавляется Basic Auth с узким исключением для пути ACME challenge, чтобы не
мешать продлению сертификата. Настоящее продление проверяется отдельно.
Проверки без пароля должны вернуть 401, с паролем — 200. Если Nginx обходит
.htaccess для статических файлов, smoke отклонит релиз и вернёт предыдущий корень:
тогда потребуется защита на уровне панели/конфигурации сервера.
Не отключать эту проверку ради успешного деплоя.

Создание файлов и реальная работа Auth на Timeweb пока не подтверждены.

## Команды на локальном компьютере

В Git Bash открыть существующий проект (не клонировать поверх него):

```bash
cd '/d/OneDrive/Documents/ChatGPT/Денорс'
bash scripts/deploy/install-command.sh
source ~/.bashrc
denors check
```

Первый запуск `denors` меняет public_html с директории на symlink, сохраняя
исходную директорию вне web root. Если хостинг не обслуживает symlink,
HTTP-проверка должна вернуть предыдущий корень. Не обходить отказ проверок.

После успешного check:

```bash
denors
```

После будущих изменений сначала выполнить соответствующие тесты и git commit,
затем `denors`. Несохранённые или незакоммиченные изменения не публикуются.
Повторный запуск SSH может запросить парольную фразу; в начале сессии:

```bash
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/denors_timeweb
```

## Совместимость с предварительной проверкой SSL

При попытке установки SSL владелец сообщил об ошибке «сайт недоступен».
Его curl подтвердил доступность HTTP с ответом 503. Для совместимости с
предварительными проверками хостинга служебная страница изменена на HTTP 200
с сохранением noindex и no-store; Retry-After удалён. Smoke и тестовая HTTP-функция
ожидают 200. Влияние этой правки на выпуск сертификата проверяется после деплоя;
ошибка ACME, DNS или проверки challenge пока не исключена.

# Отдельная БД staging

Статус: владелец сообщил имя созданной БД ci11012_denorstg; отдельное PDO-подключение
пока не проверено. На скриншоте phpMyAdmin: localhost через UNIX socket,
Percona Server 5.7.35-38, utf8mb4, сессия пользователя ci11012@localhost.
Это не подтверждает имя отдельного пользователя новой БД. PHP 7.4 на том же
скриншоте относится к phpMyAdmin и не меняет выбранный PHP 8.3 сайта.

1. Открыть «Базы данных» → «Создание новой базы данных».
2. Предлагаемый суффикс: denorstg; с префиксом аккаунта ожидается
   ci11012_denorstg. Фактическое имя подтвердить по панели.
3. Сгенерировать новый отдельный пароль и сохранить в менеджере паролей.
4. Комментарий: «Денорс — STAGING denors.site-laboratory.ru».
5. Создать пустую базу; не импортировать production dump.
6. Записать имя БД, пользователя и хост из параметров подключения. Проверить,
   что пользователь не имеет доступа к рабочим БД других сайтов.

Пароль не передавать в чат, не вставлять в команды или Git.
Для проверки подготовлен scripts/maintenance/check-db.php — только CLI.
Он читает DENORS_DB_HOST, DENORS_DB_NAME, DENORS_DB_USER, DENORS_DB_PASSWORD
из окружения отдельного процесса. Без параметров не подключается.
Проверяет версию, utf8mb4, поддержку InnoDB, begin/rollback и число таблиц.
Не создаёт таблицы и не меняет данные. Успешный begin/rollback без записи не
доказывает откат данных конкретной таблицы; это проверяется позднее с миграциями.
DB collation выводится для аудита; автоматически не изменяется.

Фактическое подключение ещё не проверялось. Для выделенной базы проверяем
пользователя с совпадающим именем ci11012_denorstg, согласно документации Timeweb.
Это проверяемое предположение, а не подтверждённый результат подключения.
В локальном Git Bash выполнить:

```bash
bash scripts/maintenance/check-db.sh
```

Диагностика отправляется по SCP в .deploy/db-check; SSH запрашивает пароль новой
БД скрыто. Пароль живёт только в окружении диагностического процесса и не
сохраняется на диск. SQLSTATE выводится без текста ошибки драйвера.
При отказе доступа сверить пользователя и пароль именно новой БД в панели.
Права не расширять на другие базы ради прохождения проверки. Настройки приложения
пока не создаются: архитектура конфигурации относится к следующему этапу.
Приватные диагностические файлы можно отправлять по SCP в .deploy, без публикации
нового релиза: настройка полной защиты staging ещё ожидает ответа поддержки.

# День 4 — точное сопоставление путей

Router хранит пары HTTP-метод / original_path. Обработчики — PHP Closure,
возвращающие Response. Никаких регулярных catch-all redirect и генерации URL
из названий товаров нет. Создание повторной пары отклоняется.

Сопоставление сохраняет регистр, слеши, percent-encoding и вложенность.
Query string не участвует в выборе пути, но это не означает автоматического
canonical для фильтров: правила определяются позже по реальным страницам.
HEAD использует GET-обработчик, Response не выдаёт тело HEAD.
Неизвестный путь → 404; неизвестный метод существующего пути → 405 с Allow.
Некорректный URI и управляющие символы → 400.

В Application зарегистрирована только главная `/`. Файл CSV не является
автоматическим источником опубликованных маршрутов: без импортированных данных
сотни пустых страниц не создаются. Controller главной и отдельная View заменили
прямое подключение шаблона в Application. Для 404 есть отдельный HTML-шаблон.

View принимает только внутреннее имя шаблона; ../ и абсолютные пути запрещены.
Данные находятся в $data, без extract; для вывода строк доступен $escape.
Пользовательские имена шаблонов и HTML из импорта не исполняются.

Apache rewrite передаёт несуществующие публичные пути в index.php без редиректа,
сохраняя REQUEST_URI. Реальные публичные файлы и директории не переписываются.
Nginx Timeweb может отдельно обрабатывать статику и некоторые кодированные URI;
PHP-тесты не заменяют проверку этих URL после публикации.

Canonical в production не генерируется пока не определены контент и политика
по эталону. В staging сохраняется noindex, а APP_ENV=production пока запрещён.
Нельзя подставлять staging-домен в будущие production canonical или sitemap.

Проверки: 15 базовых тестов приложения и 748 проверок маршрутов, включая точное
сопоставление всех 733 известных путей в тестовом реестре. Регистр, слеши,
кодированный слеш, HEAD/405, malformed URI и traversal имени шаблона проверены.
Тестовый реестр не влияет на реальный публичный Router.

Схема доменной БД и миграции ещё не реализованы: нужен фактический экспорт
WooCommerce/WordPress с ID, связями, атрибутами и Yoast. БД не изменялась.

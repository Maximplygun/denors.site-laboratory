# День 3 — минимальный каркас

Разработан локально по разрешению владельца продолжать подготовку архитектуры,
пока поддержка решает защиту staging. Это не завершение аудита и не готовый магазин.
Новый код на хостинг не публикуется до решения полной защиты.

## Границы

- PHP 8.3+, без framework и сторонних runtime-зависимостей.
- public/index.php — точка входа; публичная только папка public/.
- bootstrap/autoload.php — автозагрузка Denors\ из app/, без Composer.
- bootstrap/app.php — обработка ошибок, загрузка окружения и сборка приложения.
- config/app.php — конфигурация. .env за пределами public/; процесс имеет приоритет.
- app/Application.php — временная обработка только известного адреса главной `/`.
  GET/HEAD поддержаны, другие методы 405, неизвестные пути 404 без редиректа.
- resources/views — серверные PHP-шаблоны. Шаблон не содержит данных каталога.
- app/Http/Response.php — статус, заголовки, корректная выдача HEAD без тела.
- storage/logs — приватные ежедневные JSONL-файлы с блокировкой записи.
  Логи релиза связаны с общей storage существующим deploy-механизмом.

На этом этапе нет товарных маршрутов, миграций, запросов магазина к БД, админки,
авторизации пользователей магазина или импорта. Полноценный router и модель данных
проектируются на следующем этапе после получения фактической карты URL/экспорта.

## Конфигурация и ошибки

.env.example описывает ограниченный формат: KEY=value или KEY="literal value";
пустые строки и строки-комментарии разрешены. Нет подстановки переменных,
исполнения кода, escape-последовательностей и inline-комментариев.
Неверные строки и повторные ключи отклоняются, их значения не печатаются.
Файл не создаётся автоматически и не содержит реквизитов БД.
При отсутствии APP_ENV используется staging; разрешены только local и staging.
Production-режим явно запрещён до этапа релиза. Debug-вывод пользователю выключен.

Ошибки PHP преобразуются в исключения с учётом error_reporting. Пользователь
получает 500 и случайный код обращения; CLI получает ненулевой exit code.
В журнал записываются тип, код, файл, строка и код обращения, без исходного
сообщения, параметров запросов и аргументов stack trace. Это снижает риск записи
паролей, но означает, что подробную причину нужно воспроизводить локально.
Bootstrap parse/startup errors до регистрации обработчиков остаются под контролем
PHP/хостинга, display_errors отключён в точке входа.
Ротация по дате есть; удаление старых журналов ещё не настроено.

## Проверки и локальный запуск

```bash
php tests/application.php
php -S 127.0.0.1:8080 -t public
```

В отдельном локальном терминале открыть http://127.0.0.1:8080/.
Не использовать встроенный PHP-сервер для production.
Фактические проверки выполненного этапа записываются в roadmap.md.
Для сохранения оригинальных URL никаких новых префиксов каталога не утверждено.
